## Supersessions and scope

- P0M0's prohibition on implementing DB/agents/UI _yet_, and P0M1's prohibition on implementing
  the daemon/DB _yet_, are milestone sequencing limits. Later roadmap milestones authorize those
  implementations. Core and protocol neutrality remain mandatory.
- `@densa/*`, `densa`, `.densa/`, and protocol `0.1.0` were deliberately replaced by the canonical
  names and protocol `1.0.0` above. Old exported aliases and recorded historical paths retain only
  the compatibility promised in current documentation.
- P0M2 explicitly permits command placeholders. Legacy `project init/start` currently return
  structured unsupported-method errors, `project status` reports no selection, and doctor labels
  its agent check as a placeholder. This is limited shell behavior, not proof of complete project
  management. Phase 9 uses the dedicated proof command and typed Core v1 clients. Public CLI
  shipping/install decisions belong to Phase 10 M1.
- No later README simplification supplies an architectural replacement for P0M0's root README
  process-boundary requirement. Its deletion is an in-scope regression.
